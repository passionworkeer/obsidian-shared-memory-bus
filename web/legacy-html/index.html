核心特性

本地优先的工程级记忆系统

不是又一个云笔记,而是把记忆当作本地数据基础设施来设计。

共享记忆

Claude Code 写入的项目背景,Codex 和 Cursor 下一次会话直接读取。跨工具、跨会话保留上下文。

本地优先

数据存在本地 .ai-memory/ 目录,默认不联网,不依赖任何 SaaS。可离线运行。

混合检索

BM25 关键词 + 语义向量双重召回,内置中文分词,既精准又理解近义。

MCP 协议

原生支持 Model Context Protocol,任何 MCP 兼容工具都能接入,不写适配器。

watchdog 自动同步

后台观察者进程监听各工具记忆文件,自动归并去重写入 canonical store,无需手动触发。

6 层记忆分层

Working / Session / Essential / Durable / Reference / Archive,按生命周期和成本自动归档。

系统架构

四层结构,职责清晰

从客户端到存储,每一层都可独立替换或扩展。

01

AI Clients

接入层

任何支持 MCP 协议的 AI 编程工具都可作为客户端。每个工具保留各自原生的记忆格式,由 bus 统一翻译。

02

Shared MCP Layer

协议层

本地 MCP 服务器集群对外提供统一接口。memory:9338 是核心,fetch / time / context7 / playwright 是配套工具。

03

Local Runtime

检索层

bus / watchdog 进程编排写入与同步。BM25 + Dense + Hybrid 三路检索并行召回,本地 LSH 哈希或可选 OpenAI/HF 向量。

04

Canonical Store

存储层

.ai-memory/ 是唯一可信来源。structured / inbox / generated 三种用途的 JSONL 文件,所有工具最终都收敛到这里。

记忆分层

L0 — L5 阶梯式生命周期

不同热度、不同成本的记忆自动落到合适的层级。

  1. L0Working
    当前会话工作内存 · 内存
  2. L1Session
    短时记忆 · 7 天滚动 · .ai-memory/session/
  3. L2Essential
    关键项目信息 · .ai-memory/structured/
  4. L3Durable
    长期知识库 · 进向量空间 · .ai-memory/durable/
  5. L4Reference
    参考文档 · .ai-memory/reference/
  6. L5Archive
    归档 · 不进向量空间 · archive-manifest.jsonl

快速开始

4 步完成接入

需要 Node.js ≥ 18。整个过程在本地完成,无需注册账号。

1 克隆仓库 
git clone https://github.com/passionworkeer/local-ai-memory-bus.git
cd local-ai-memory-bus
2 安装依赖 
npm install
3 启动 MCP 服务器 
node start.js

也可双击 start.bat(Windows)。

4 配置客户端 
node setup-mcp.js

自动检测 Claude Code 并写入配置。重启客户端即可使用共享记忆。
