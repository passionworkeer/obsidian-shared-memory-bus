# 2026-04-10

## Fix: Windows Background Runtime Launchers

The shared MCP Windows launchers now use a three-layer console-hiding approach to reliably keep background Node.js processes invisible:

1. `Start-Process -WindowStyle Hidden` on the initial launcher call.
2. A helper launcher script (`run-obsidian-mcp.ps1`, `run-minimax-mcp.ps1`, etc.) that re-launches the actual process with a second `Start-Process -WindowStyle Hidden` call, covering cases where the first layer is bypassed.
3. A background launcher wrapper that is itself launched hidden before it spawns the helper layer.

The `singleton-stdio-mcp-proxy.mjs` was also made more robust to handle edge cases in background execution. Additionally, a new `ops/install-client-integrations.ps1` script was added to streamline client integration installation on Windows.

## Fix: Hardened Windows Shared MCP Fallback and Validation

`shared-mcp/start-shared-mcp.ps1` was significantly strengthened:

- Improved fallback logic when primary MCP servers fail to start.
- Better process lifecycle management to reduce orphaned processes.
- `shared-mcp/manifest.json` updated to reflect current server configurations.

`ops/verify-client-integrations.ps1` now has expanded client integration checks. `ops/run-pressure-test.ps1` was hardened with broader coverage for validation probes.

## New: Comprehensive Windows Installer

A new `scripts/install.ps1` provides a guided installer for the full memory bus on Windows, including background launcher setup and client integration registration.

## New: memory_wake_up Tool and Verbatim Snippet Extraction

The memory MCP server now includes a `memory_wake_up` tool that builds a compact session bootstrap pack from the canonical shared memory bus, including HANDOFF records, MEMORY-LAYERS, and active task records. The `search_shared_memory` tool gains three new parameters:

- `includeVerbatim` — attach query-aware exact snippet windows to results.
- `snippetWindow` — control the character window around each match.
- `maxVerbatimPerResult` — limit snippets per result.

`ops/check-memory-integrity.js` was added to verify structured JSONL files follow the versioned memory contract schema.

## Other Changes

- `shared-mcp/memory-status.js` now calls `memory_wake_up` internally to build its bootstrap pack.
- `docs/TROUBLESHOOTING.md` expanded with new Windows-specific guidance.
- `docs/ENVIRONMENT.md` updated to cover all current environment variables.
- `docs/reference/MCP-TOOLS.md` and its JSON schema updated for new tool parameters.
- `bus/memory-watchdog.ps1` watchdog improvements for more reliable auto-restart.
